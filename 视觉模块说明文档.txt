1. 视觉模块的角色与系统边界
================================================================

1.1 角色定位
----------------------------------------------------------------
视觉模块是取放物阶段的"指挥者"：
- 机器人板负责"走到哪"（循迹 + 路径表）；
- 视觉模块负责"抓什么、放哪、怎么动"（识别包裹位置，
  通过串口下发坐标与动作指令，逐步指挥 4 自由度机械臂）。

职责边界（重要，写报告时体现分工）：
 视觉模块管：包裹识别、坐标解算、取放动作指令、
             到位判定（视觉观察/时序控制）、完成判定
 机器人板管：到达判定、状态机切换、逆运动学解算、
             机械臂指令执行（USART3单向下发）
 双方共管：  通过完成帧（0x20/0x21，含status）确认阶段结果，
             状态机才允许流转

1.2 两个生效场景
----------------------------------------------------------------
- GRAB（取物）：小车到达取货点，H板收到 CMD_HANDOVER 后触发
- DROP（放物）：小车返回原点，H板收到 CMD_HANDOVER 后触发
其余状态下视觉模块不发送动作指令（权力交接制：未持权不发言），
仅存在握手（TEST回显）与 ACK 应答。

2. 通信链路与握手
================================================================

2.1 链路参数（协议V1.5已定，v1.0占位全部落地）
----------------------------------------------------------------
物理接口   UART（接机器人板 USART6 PC6/PC7）
波特率     115200，8N1
帧头       0xA5
帧结构     帧头(1B)+长度(1B)+命令字(1B)+数据体(N)+校验和(1B)
           +帧尾(0x0D 0x0A)；数据体转义编码（转义表见协议第三章）
校验       长度+命令字+转义后数据体累加和取低8位
协议实现   直接移植统一 protocol.c（C代码可编译，
           与F板/ESP32-S3三端同源）

2.2 握手流程（上电阶段）
----------------------------------------------------------------
 上电 --> F板经串口发 TEST(0xFF)
        --> 视觉模块【原样回一帧TEST】（非ACK）
        --> 链路确认，F板LED常亮进入待命
- F板是发起方，视觉模块全程被动应答；
- F板超时500ms重发，最多3次；
- 握手实现要点：收到0xFF原样回显，不需要任何状态判断，
  是最简单的实现路径。

2.3 ACK 规则
----------------------------------------------------------------
- 凡协议内命令（交权/坐标/爪/完成帧等），收到一律回ACK
  （0x00），无一例外；重复帧同样回ACK（幂等）；
- 未知命令码丢弃不回；
- ACK只代表"收到并开始执行"，F板动作是否做完由视觉自行判断。

3. 全任务时序中的视觉模块（总览）
================================================================
机器人板状态机：
 STANDBY -> PLAN -> RUN_OUT -> GRAB -> PLAN_BACK -> RUN_BACK
 -> DROP -> 回 STANDBY

视觉模块的活跃区间（只在其中两个状态持权发指令）：
 STANDBY    [空闲，仅TEST回显/ACK应答]
 PLAN       [空闲]
 RUN_OUT    [空闲，可做预识别准备——见4.1备注]
 GRAB       [活跃] 收HANDOVER交权 -> 识别 -> 下发取物指令序列
            -> 发GRAB_DONE -> 交还控制权
 PLAN_BACK  [空闲]
 RUN_BACK   [空闲]
 DROP       [活跃] 收HANDOVER交权 -> 下发放物指令序列
            -> 发PLACE_DONE -> 交还控制权

时序要点：
- 进入 GRAB/DROP 的触发者是机器人板（到达判定后发
  CMD_HANDOVER），不是视觉模块——视觉模块被动接管；
- 阶段同步已由协议命令落地：
  阶段开始 = CMD_HANDOVER(0x01)，
  阶段结束 = GRAB_DONE(0x20)/PLACE_DONE(0x21) + 交还HANDOVER。

4. 取物阶段（GRAB）工作流程
================================================================

4.1 阶段进入
----------------------------------------------------------------
- 前置条件：机器人板循迹到达取货点（四路全黑+计数匹配）停车
- F板 -> H板 : CMD_HANDOVER(0x01)，H板回ACK——视觉模块接管
- （备注：若视觉模块支持，可在 RUN_OUT 途中预先识别，
  交权后直接下发结果，缩短取物耗时——是否实现【待定】）

4.2 指挥流程（视觉模块主导，逐条执行）
----------------------------------------------------------------
 视觉识别包裹位置
   v
 下发 CMD_MOVE_COORD(0x10, x/y/z坐标，符号+幅值编码)
   --> F板回ACK后执行逆运动学解算 -> USART3单向下发关节角
   （F板无舵机回传，视觉自行判断到位：观察/时序）
   v
 下发 CMD_CLAW_CLOSE(0x11) --> F板回ACK后收紧机械爪
   v
 ……逐条推进，直至取物动作序列完成
   v
 视觉确认抓稳（方式二选一【待定】：视觉观察 / 时序控制）
   v
 H板 -> F板 : CMD_GRAB_DONE(0x20, status=0成功/1失败)，F板回ACK
   v
 H板 -> F板 : CMD_HANDOVER(0x01)（控制权交还），F板回ACK
   v
 （status=0时 F板向HMI发PICKED；status=1时 F板上报ERROR(0x04)
   任务终止——见第7章）

4.3 执行链路说明（写报告可画此图，v1.1 修正）
----------------------------------------------------------------
 视觉模块              机器人板F板              机械臂
 ------------        ------------            --------
 识别包裹位置
 ---CMD_MOVE_COORD-> 逆运动学解算
    (H板回ACK确认)    (视觉坐标->4维关节角)
                     ---USART3(TX单向)--->  4自由度总线舵机
 到位判定
 (视觉观察/时序控制，F板无舵机回传，确认责任在视觉端)
 确认到位，发下一条指令

要点：
- 机器人在GRAB状态下是"执行通道"，不自主决策动作；
- 每条指令"下发->ACK->执行->视觉判定到位->下一条"串行推进；
- 坐标体系：视觉下发的x/y/z坐标与机械臂4维关节角之间的
  映射（逆运动学）在F板完成；视觉坐标系的标定
  【待定：标定方法与数据，装车后完成】；
- 关键设计：USART3仅TX单向，到位确认不靠回读、
  靠视觉观察或时序控制——这是本模块的核心设计约束。

5. 放物阶段（DROP）工作流程
================================================================

5.1 阶段进入
----------------------------------------------------------------
- 前置条件：机器人板循迹返回原点（计数匹配）停车
- F板 -> H板 : CMD_HANDOVER(0x01)，H板回ACK——视觉模块接管

5.2 指挥流程（v1.1 补交权步骤）
----------------------------------------------------------------
- 视觉模块逐条下发放物指令序列：
  CMD_MOVE_COORD（抬升/平移到放下位）-> CMD_CLAW_OPEN（放开）
  -> 回收动作
- 动作序列完成后：
  H板 -> F板 : CMD_PLACE_DONE(0x21, status)，F板回ACK
  H板 -> F板 : CMD_HANDOVER(0x01)（控制权交还），F板回ACK
- （status=0时 F板向HMI发DELIVERED，DROP结束回STANDBY；
  status=1时 F板上报ERROR(0x05)任务终止）
- 【v1.1 明确】放物完成后必须交还控制权——
  不交权则F板无法回到STANDBY接受新任务。

5.3 与取物的差异点
----------------------------------------------------------------
- 取物需要"识别"环节（包裹位置未知），放物通常位置已知
  （原点固定放下位），指令序列可预生成，
  耗时应明显短于取物——报告可对比两阶段耗时【实测后填】

6. 机器人板侧的接收分发机制（状态门控）
================================================================
（此机制在机器人板侧实现，视觉模块需理解其行为以便对齐）

核心认知：串口全双工，物理上不存在抢线；跨板指令时序由协议
"权力交接制"约定，板内解析干扰由状态门控分发解决——
交接是跨板语义，门控是板内实现，两者不矛盾。

F板串口B收到帧：
 |-- 状态=GRAB/DROP(已交权) -> 解析坐标/爪/完成帧，交执行
 |-- 状态=未持权            -> 仅处理TEST/ACK，动作指令丢弃
 +-- 未知命令码             -> 丢弃不回ACK

- 取物与放物共用一条物理链路，靠交权状态区分语义；
- 实现收口为 uart_b_dispatch()（见主控文档v0.7 5.3）。

7. 异常与超时处理
================================================================
场景                            处理
----------------------------------------------------------------
GRAB/DROP阶段60s无动作指令      F板报警兜底，状态保持
（H板未发/链路异常）            （参数【待定】）
动作指令执行中F板发不出/        USART3仅TX，F板无法检测舵机
舵机异常                        异常的执行结果；
                                舵机无响应由F板检测 ->
                                上报ERROR(0x02)终止
视觉识别失败（未找到包裹）      视觉模块持续搜索，
                                长时间未找到 -> 视觉搜索超时
                                -> F板上报ERROR(0x03)终止
                                （搜索时长阈值【待定】）
抓取动作失败                    H板发GRAB_DONE(status=1)
                                -> F板上报ERROR(0x04)，
                                任务终止
放包裹动作失败                  H板发PLACE_DONE(status=1)
                                -> F板上报ERROR(0x05)，
                                任务终止
任一指令3次重发无ACK            置0x07通信故障，任务终止
阶段进行中链路中断              F板状态冻结+LED闪烁，
                                链路恢复后从断点续跑
                                【断点续传粒度待定，简化方案：
                                整个阶段重跑】

报告里值得强调的设计点（体现思考深度）：
- 职责划分：机器人板管"去哪"，视觉管"怎么抓"，
  完成帧（含status）作为状态机流转与故障上报的凭据；
- 权力交接制（跨板语义）+ 状态门控分发（板内实现）的
  两层设计，职责清晰且互不冲突；
- USART3仅TX单向的约束下，到位确认责任转移到视觉端
  （视觉观察/时序控制）——硬件简化（省一路UART双向）
  换软件确认机制，是一次明确的取舍论证；
- 三端协议同源移植 protocol.c，避免实现不一致。
