一、整体通信架构
================================================================

      ┌──────────────────┐   ┌──────────────────┐   ┌──────────────┐
      │   人机交互(HMI)  │   │     控制板(F板)  │   │  视觉模块(H板)│
      │    ESP32-S3      │   │   STM32F407      │   │    OpenMV    │
      │  ST7262+GT911    │   │  ┌─────────┐     │   │              │
      │  状态机/协议/UI  │   │  │ESP8266  │WiFi │   │              │
      └────────┬─────────┘   │  │转发程序 │     │   └──────┬───────┘
               │             └──┴────┬────┴─────┘          │
               │   WiFi(经F板侧ESP8266中继) │ USART6(PC6,PC7)
               │                     │                     │
               │<───── 帧协议 0x5A ──┤                     │
               │  取件码/启动/停止/ACK│  TEST/交权/坐标/爪 │
               │                     │────────────────────>│
               │  PICKED/DELIVERED/  │                     │
               │  ERROR/RESUME/ACK   │                     │
               │────────────────────>│<────────────────────│
               │                     │  ACK/交权/爪/动作完成│
               │                     │                     │
               │                     │ USART3(PB10,仅TX)   │
               │                     │────────>│ 总线舵机  │
               │                     │  (单向) │ 4自由度   │

通信链路：
┌─────────────────┬──────────────────┬────────────┬──────────┐
│ 通信链路        │ 硬件接口         │ 帧头标识   │ 波特率   │
├─────────────────┼──────────────────┼────────────┼──────────┤
│ F板 ↔ HMI       │ USART2(PD5,PD6)  │ 0x5A       │ 115200   │
│                 │ 经F板侧ESP8266   │            │          │
│                 │ (自写转发程序)   │            │          │
│                 │ WiFi中继至ESP32-S3            │          │
│ F板 ↔ 视觉模块  │ USART6(PC6,PC7)  │ 0xA5       │ 115200   │
│ F板 ↔ 总线舵机  │ USART3(PB10 TX)  │ —          │ 115200   │
└─────────────────┴──────────────────┴────────────┴──────────┘

说明：
· HMI 主控为 ESP32-S3（ST7262显示+GT911触摸）；F板侧挂 ESP8266
  作为 WiFi 模块，运行自写转发程序（非AT透传），只做双向字节
  搬运，不解析协议帧——协议两端（STM32/ESP32-S3）同源移植
  protocol.c，中间转发层对协议完全透明；
· HMI 与控制板通信量很小：上行仅取件码+启动+停止+ACK，
  下行仅状态事件+故障+恢复+ACK；
· 视觉模块与控制板之间采用"权力交接制"：谁持有控制权谁主动发
  消息，另一方静默等待；交接通过 CMD_HANDOVER 双向完成；
· 总线舵机由 F 板直接驱动，逆运动学解算在 F 板完成；
  USART3 仅 TX 单向发送，F 板收不到舵机回传——机械臂是否到位
  由视觉模块自行判断（视觉观察或时序控制），本协议据此设计。

二、统一帧结构
================================================================

┌──────────┬──────────┬──────────┬────────────┬──────────┬───────────┐
│  帧头    │  长度    │  命令字  │   数据体   │  校验和  │  帧尾     │
│  (1B)    │  (1B)    │  (1B)    │  (N字节)   │  (1B)    │  (2B)     │
├──────────┼──────────┼──────────┼────────────┼──────────┼───────────┤
│  0xA5    │ 数据长度 │  命令码  │   数据体   │  累加和  │ 0x0D 0x0A │
│  或 0x5A │          │          │            │          │           │
└──────────┴──────────┴──────────┴────────────┴──────────┴───────────┘

字段说明：
┌────────────┬─────────────────────────────────────────────────────────┐
│ 字段       │ 说明                                                    │
├────────────┼─────────────────────────────────────────────────────────┤
│ 帧头       │ 0xA5 = 视觉模块(H板)，0x5A = 人机交互模块(ESP32-S3)     │
│ 长度       │ 数据体字节数(转义前的原始长度，不含帧头/长度/校验/帧尾) │
│ 命令字     │ 具体操作指令(见命令字定义表)                            │
│ 数据体     │ 可变长度，根据命令字不同而不同，转义编码后发送          │
│ 校验和     │ 长度字节+命令字+转义后数据体 所有字节累加(取低8位)      │
│ 帧尾       │ 固定 0x0D 0x0A                                          │
└────────────┴─────────────────────────────────────────────────────────┘

三、转义规则
================================================================
数据体中出现与帧头/帧尾/转义符相同的字节时，替换为两字节转义序列：

┌────────────────────┬────────────────────┐
│      原始字节      │      转义后        │
├────────────────────┼────────────────────┤
│       0xA5         │     0x7D 0x01      │
│       0x5A         │     0x7D 0x04      │
│       0x0D         │     0x7D 0x02      │
│       0x0A         │     0x7D 0x03      │
│       0x7D         │     0x7D 0x00      │
└────────────────────┴────────────────────┘

注意：
· 0xA5 与 0x5A 使用两个独立转义码，解码与帧头上下文无关，无损还原；
· 转义只作用于数据体，帧头/长度/命令字/校验和/帧尾不转义；
· 三端(控制板/ESP32-S3/OpenMV)必须使用同一份转义表，否则无法互调。

四、命令字定义表
================================================================

4.1 人机交互模块命令(帧头 0x5A)
（模块侧行为细节见《人机交互模块工作流程说明文档 V1.4》）

┌────────────┬───────┬──────────────────┬──────────────────────────┐
│ 命令字     │ 方向  │ 含义             │ 数据体                   │
├────────────┼───────┼──────────────────┼──────────────────────────┤
│ 0x00       │ 双向  │ ACK命令应答      │ 无                       │
│ 0xFF       │ 双向  │ 连接测试(TEST)   │ 无                       │
│ 0x10       │ HMI→F │ 下发取件码       │ 3字节ASCII数字('0'~'9')  │
│ 0x11       │ HMI→F │ 启动指令         │ 无                       │
│ 0x12       │ HMI→F │ 停止指令         │ 无                       │
│ 0x13       │ F→HMI │ 已取到包裹       │ 无                       │
│ 0x14       │ F→HMI │ 已送达           │ 无                       │
│ 0x15       │ F→HMI │ 故障上报         │ 1字节故障码              │
│ 0x16       │ F→HMI │ 受阻恢复通知     │ 无                       │
│            │       │ (CMD_HMI_RESUME) │                          │
└────────────┴───────┴──────────────────┴──────────────────────────┘

取件码说明：
3位十进制数字，逐字节发送其ASCII码值。
例：取件码"205" → 数据体 0x32 0x30 0x35 (3字节)。
取件码与货架的对应关系由 F 板查表决定。
发送时机：用户点击"确定"仅本地保存并显示，点击"启动"时
才随 CMD_START 一起发给 F 板。

0x16 使用场景：
F板因前方受阻(0x08)停车等待人工移障，障碍移除后，F板发送
CMD_HMI_RESUME 通知 HMI 恢复原状态显示，随后任务继续。
该命令是 HMI 清除"受阻"提示、恢复进度显示的凭据。

4.2 视觉模块命令(帧头 0xA5)
（视觉指挥机械臂的完整流程见《视觉模块工作流程说明文档 v1.1》）

┌────────────┬───────┬──────────────────┬──────────────────────────┐
│ 命令字     │ 方向  │ 含义             │ 数据体                   │
├────────────┼───────┼──────────────────┼──────────────────────────┤
│ 0x00       │ 双向  │ ACK命令应答      │ 无                       │
│ 0xFF       │ 双向  │ 连接测试(TEST)   │ 无                       │
│ 0x01       │ 双向  │ 交出控制权       │ 无 (谁收到谁接管)        │
│ 0x10       │ H→F   │ 移动到指定坐标   │ sx+x+sy+y+sz+z 共6字节   │
│ 0x11       │ H→F   │ 机械爪收紧       │ 无                       │
│ 0x12       │ H→F   │ 机械爪放开       │ 无                       │
│ 0x20       │ H→F   │ 抓取动作完成     │ 1字节(0=成功,1=失败)     │
│ 0x21       │ H→F   │ 放包裹动作完成   │ 1字节(0=成功,1=失败)     │
└────────────┴───────┴──────────────────┴──────────────────────────┘

坐标编码说明：
每轴占2字节，共6字节：
┌──────────┬──────────┐
│ 第1字节  │ 第2字节  │
│  符号    │  幅值    │
│ 0x00=正  │  0~255   │
│ 0x01=负  │  (mm)    │
└──────────┴──────────┘

· 设计依据：机械臂工作空间最大不超过255mm，单字节幅值足够；
  符号独立一字节表示，避免二进制补码跨字节解析歧义；
· 示例：x = -90mm → 数据体字节 0x01 0x5A
        y =  45mm → 数据体字节 0x00 0x2D
· 组帧时若任一轴幅值超过255，组帧函数直接拒绝返回失败；
· 幅值中出现的 0x5A/0x7D 等字节由转义层自动处理，应用层无需关心。

五、故障码定义表（三板统一）
================================================================

┌────────────┬──────────────────────┬────────────────────────────────┐
│ 故障码     │ 名称                 │ 触发条件                       │
├────────────┼──────────────────────┼────────────────────────────────┤
│ 0x01       │ 电机驱动故障         │ 轮子电机不转/编码器无反馈      │
│ 0x02       │ 舵机通信故障         │ 总线舵机无响应/驱动异常        │
│ 0x03       │ 视觉搜索超时         │ 视觉模块长时间未找到目标       │
│ 0x04       │ 抓取失败             │ 重试后仍失败                   │
│ 0x05       │ 放包裹失败           │ 重试后仍失败                   │
│ 0x06       │ 路径规划失败         │ 起点到目标无可行路径           │
│ 0x07       │ 串口通信超时         │ 任一命令重发3次仍无ACK         │
│ 0x08       │ 前方受阻             │ 循迹行驶中超声波测距 < 阈值，  │
│            │ 【可恢复】           │ 停车等待人工移障               │
│ 0x09       │ 超声波故障           │ HSRC04 ECHO连续无效超限，      │
│ (V1.5新增) │                      │ 障碍检测能力丧失，任务终止     │
└────────────┴──────────────────────┴────────────────────────────────┘

故障码分类（V1.5 明确）：
· 0x01~0x07、0x09：任务终止型故障。检测方上报后，HMI 收到
  显示故障码、状态机复位回待取件，需用户重新启动任务；
· 0x08：可恢复型故障（唯一）。障碍移除后任务继续，HMI 收到
  显示"前方受阻，等待移障"但【不复位状态机】，等待
  CMD_HMI_RESUME(0x16) 后恢复原状态显示。

各故障码的检测方与上报路径（V1.5 补全）：
┌────────┬──────────────┬──────────────────────────────────────┐
│ 故障码 │ 检测方       │ 上报路径                             │
├────────┼──────────────┼──────────────────────────────────────┤
│ 0x01   │ F板          │ F板 → HMI : CMD_ERROR(0x01)          │
│ 0x02   │ F板          │ F板 → HMI : CMD_ERROR(0x02)          │
│ 0x03   │ H板(视觉)    │ H板 → F板(动作完成帧status或异常通知)│
│        │              │ → F板 → HMI : CMD_ERROR(0x03)        │
│ 0x04   │ H板          │ H板发GRAB_DONE(status=1) → F板       │
│        │              │ → HMI : CMD_ERROR(0x04)              │
│ 0x05   │ H板          │ H板发PLACE_DONE(status=1) → F板      │
│        │              │ → HMI : CMD_ERROR(0x05)              │
│ 0x06   │ F板          │ F板 → HMI : CMD_ERROR(0x06)          │
│ 0x07   │ 发送方判定   │ 按第六节第4条规则处置                │
│ 0x08   │ F板(超声波)  │ F板 → HMI : CMD_ERROR(0x08)          │
│ 0x09   │ F板(超声波)  │ F板 → HMI : CMD_ERROR(0x09)          │
└────────┴──────────────┴──────────────────────────────────────┘

0x08 附加规则：
· F板侧：停车、关电机、状态机冻结在 RUN_OUT/RUN_BACK，
  恢复条件 = 连续5次(间隔200ms)测距 >= 阈值(30cm)；
· 0x08 的上报与恢复均遵循统一 ACK/重传规则
  （重传3次无ACK → 按0x07流程处理，但车保持停车状态）；
· 受阻期间用户可发 CMD_STOP 正常终止任务
  （车本来就在停车，无运动冲突）；
· 超声波测距连续无效（ECHO不回落/无反射）→ 视为测距无效，
  不触发0x08（宁可靠近一点也不能误停死在路上）；
  连续无效超限 → 上报0x09，任务终止。

备注（预留，V1.5 不实现）：低电量告警如需上报 HMI，
须新增故障码，且为"告警不复位"类型（与0x08同类）。
当前低电量仅 F板本地蜂鸣器报警，不走协议。

六、ACK 与重传机制（本协议核心规则）
================================================================

1. 连接测试(CMD_TEST_LINK, 0xFF)：
   仅用于上电链路自检。F板分别向 HMI 和视觉模块各发一帧 TEST，
   对方原样回一帧 TEST，收到回复即链路就绪；
   超时未回按下方重传规则处理（500ms x 3）。
   注：TEST 回复用原样回显而非 ACK——语义分离
   （链路活着 vs 命令已执行），且回显可校验帧完整性。

2. ACK 应答范围：
   【所有】跨板命令均需 ACK 应答，无一例外：

   ┌─────────────────────┬─────────────────────┐
   │ 命令                │ 谁回ACK             │
   ├─────────────────────┼─────────────────────┤
   │ 取件码/启动/停止    │ F板                 │
   │ PICKED/DELIVERED/   │ HMI                 │
   │ ERROR(含0x08/0x09)/ │                     │
   │ RESUME              │                     │
   │ 交权/坐标/机械爪    │ F板                 │
   │ GRAB_DONE/PLACE_DONE│ F板                 │
   └─────────────────────┴─────────────────────┘

   总规则：凡是协议内定义的命令，收到一律回ACK（含重复帧）；
   唯一例外：协议外的未知命令码 → 丢弃不回
   （回ACK会掩盖故障——发送方误以为命令已被理解执行）。

3. ACK 语义：
   ACK 仅表示"命令已接收并开始执行"，不代表动作完成。
   舵机为 F 板单向驱动(USART3 仅TX)，无回传；动作是否到位由
   视觉模块自行判断(视觉观察/时序控制)，收到 ACK 后自行决定
   下一步。一问一答两层：ACK管"你听到没"，事件帧管"你做完没"。

4. 重传机制：
   · 任何需要 ACK 的命令发出后启动超时计时
     （有线链路 200~500ms；F板↔HMI 经WiFi中继，取 500ms）；
   · 超时未收到 ACK → 原样重发该帧，最多重发 3 次；
   · 重发 3 次后仍未收到 ACK → 判定通信故障，置故障码 0x07：
     - 若发送方是 F 板 → F板向 HMI 上报 ERROR(0x07)，任务终止；
     - 若发送方是 HMI → HMI 显示"通信故障"，状态复位回待取件；
     - 若发送方是 H 板 → F板向 HMI 上报 ERROR(0x07)，任务终止；
   · 重发期间收到 ACK 立即停止重发；
   · 接收方对重复收到的同一命令应幂等处理(重复执行无副作用)，
     简单做法：状态未变化的重复通知直接回ACK即可。
     （0x08 幂等特例：重复收到的 ERROR(0x08) 直接回ACK，
      保持"受阻"显示不变，不重复计时不清提示。）

================================================================
七、通信流程总览（阶段索引 + 异常分支）
================================================================
完整任务时序分七个阶段，各阶段的模块侧执行细节见对应模块文档：

  阶段零  上电连接测试          本文档 第六节第1条
  阶段一  用户下达任务          HMI 模块文档 V1.4
  阶段二  小车前往货架          主控文档 v0.7
  阶段三  权力交接(取包裹)      视觉模块文档 v1.1
  阶段四  视觉识别与抓取        视觉模块文档 v1.1
  阶段五  控制权交还，返航      主控文档 v0.7
  阶段六  权力交接并放包裹      视觉模块文档 v1.1

异常分支（三板共同约定）：
· 任一动作失败(GRAB_DONE/PLACE_DONE status=1)
  → F板 → HMI : CMD_ERROR(0x04/0x05)，HMI回ACK后显示故障，
    复位回待取件，任务终止；
· 视觉搜索超时 → F板 → HMI : CMD_ERROR(0x03)；
· 电机驱动故障 → F板 → HMI : CMD_ERROR(0x01)；
· 舵机通信故障 → F板 → HMI : CMD_ERROR(0x02)；
· 路径规划无可行路径 → F板 → HMI : CMD_ERROR(0x06)；
· 超声波连续无效超限 → F板 → HMI : CMD_ERROR(0x09)；
· 任一命令重发3次仍无ACK → 置0x07(见第六节第4条)；
· HMI 发送 CMD_STOP → F板立即停车，任务终止，HMI回到待取件。

障碍分支（可恢复，与上述终止型分支并列）：
    循迹行驶中(RUN_OUT/RUN_BACK)
      v
    超声波测距 < 30cm -> 停车，关电机，状态冻结
      v
    F板 → HMI : CMD_ERROR(0x08)，HMI回ACK
      v
    HMI 显示"前方受阻，等待移障"，状态机保持不变
      v
    （人工移除障碍物）
      v
    连续5次(200ms间隔)测距 >= 30cm
      v
    F板 → HMI : CMD_HMI_RESUME(0x16)，HMI回ACK
      v
    HMI 恢复原状态显示，F板原地恢复循迹，任务继续

  特殊约定：
  - 0x08 是唯一"不复位任务"的故障码（其余均终止）；
  - 受阻期间点击STOP → 照常终止复位；
  - 0x08/0x16 重传3次无ACK → 按0x07通信故障处理，
    车保持停车状态。
